# 禁止構文と置換

現状のコードに存在するかどうかは関係なく、**規範として禁止**する。
見つけたら直す。直せない場合は理由を出力する。

2026-11 の20文サンプルで、受身・「のみ」・カタカナ語は **禁止ではない** と確認した。
文法の整理ではなく、情報の過不足を見る。

## A. 機械的に直す

| パターン（正規表現） | 何が悪いか | 置換の方針 |
|---|---|---|
| `することができ` | 冗長 | 「できます」または動詞化 |
| `していただ` / `させていただ` | 過剰敬語 | 削る、または「します」 |
| `の方は` | 区分の冗長 | 「〜は」 |
| `に関して(は|の)?` / `についての` | 冗長 | 「〜の」「〜は」、または削る |
| `という(こと|もの)` | 冗長 | 削る |
| `を行(い|う)` | 名詞化 | 動詞化（「設定を行う」→「設定する」） |
| `から行え(ます|る)` | 名詞化 | 「〜でできます」 |
| `とても` / `非常に` / `かなり` / `様々な` / `さまざまな` / `多様な` | 誇張・空虚 | 削る、または具体的な量を書く |
| `シームレス` / `直感的` / `スマート` / `パワフル` / `多機能` / `包括的` / `革新的` / `最適化` | マーケティング語 | 具体的な動作で書く |
| `エラーが発生しました` / `問題が発生しました` | 原因不明 | 何が失敗したかを書く |
| `もう一度お試しください` | 回復手段がない | 原則削る。次の操作が明確な場合だけ具体的に書く |
| `各.{0,8}それぞれ` | 二重 | 片方を削る |
| `描画され` / `レンダリングされ` / `処理され` | 実装語の漏れ | 利用者から見た結果で書く |
| `右上の` / `左上の` / `右側の` / `左側の` | 位置依存 | ボタン名で指示する |
| `\.\.\.` | 表記 | `…` |
| `！` / `!` | 誇張 | 削る |
| `\u3000`（全角空白） | 表記 | 削る |

## B. 文脈で判断する

| パターン | 判断 |
|---|---|
| 情緒的なタグライン・比喩・余韻 | 削除する。機能を書く |
| 文脈で明らかな状態の前置き | 削除する（「既に保存されています。上書きしますか？」→「上書きしますか？」） |
| `のみ` | **残してよい**。過剰な重複があるときだけ「だけ」に |
| 受身（保存されます・配置されます・調整されます） | **残してよい**。問題は実装語だけ |
| カタカナ語（スキップ・カラーテーマ） | **残してよい**。意味が正確なら和語にしない |
| `〜できません` の禁止形 | 状態で書けるなら状態にする（「使用できません」→「重複しています」） |
| `自動で` / `自動的に` | **「自動的に」** に寄せる |
| `くらい` / `ほど`（数量の目安） | 未検証。曖昧なら断言するか範囲を書く |
| `により` / `によって` | 未検証。冗長なら「で」 |
| `場合` | 条件が単純なら「とき」 |
| `〜を。」で終わる断片 | 余韻目的なら文にする |
| 体言止めの連打 | 見出しは可。本文では文にする |
| `まず` / `次に` / `最後に` | 手順説明以外では削る |
| `こちら` / `そちら` | 具体名にする。空状態の「ここ」は可 |
| 列挙（A・B・C） | 一般化する。ただしプライバシーとデータの扱いは明示する |
| レイアウト依存の表現 | 「右上の」は禁止。文脈的な「ここ」は可 |

## C. 表記

- 句読点は全角の `、` `。`。ラベル・ボタン・見出しの末尾に `。` は付けない。
- 三点リーダは `…`。文中の省略は `……` も可。
- 数字は半角。助数詞は詰める（`3冊`、`2文字`、`7日間`）。
- 英字は半角。日本語との間隔は未検証（現状は混在）。
  `EPUBを追加` と `TTF / OTF / TTCを追加` のどちらかに統一する。
- スラッシュ区切りの列挙は前後に半角スペース（`TTF / OTF / TTC`、`縦書き / 横書き`）。
- 中黒は詰める（`表示・フォント・外観`）。
- 括弧は日本語なら全角 `（）`。ASCII だけの補足は半角 `()` 可。
- UI ラベル・画面名は `「」`。書名は `『』`。階層は `「設定 > フォントマネージャー」`。

## D. エラー文言

1. **何が失敗したか**を1文で書く。主語は省略してよい。
2. **回復手順を足さない。** 次の操作が明確な場合だけ1文追加する。
3. 原因を推測しない。「もう一度お試しください」を機械的に付けない。
4. 読者を責めない（「正しく入力してください」は禁止）。
5. 状態で書けるなら状態で書く（「重複しています」）。

## E. 直せないとき

意味が変わる、仕様が不明、用語が未決のときは、無理に置換しない。
出力の「保留した箇所」に、理由と選択肢を書く。
