# スロット別の規則

同じ画面でも、スロットによって文体・句読点・長さが変わる。
ここにないスロットは、最も近いものを適用する。

## 全体

- **機能を書く。** 情緒・比喩・余韻・タグラインは置かない。
- **文脈で分かることは書かない。** タイトル・見出し・直前の文で分かる状態を繰り返さない。
- **説明より状態、禁止より診断。** 「使用できません」ではなく「重複しています」。
- **1文1意**。1文に読点は2つまで。超えたら分割する。
- 1文は **40字以内** を目安にする。
- 同じ情報を2か所に書かない（画面名・見出し・説明の三重化を避ける）。
- 画面名を本文で繰り返さない。
- **列挙より一般化する。** ただしプライバシーとデータの扱いは明示的に保証する。
  - 例: 「本棚・本文・…は端末内にのみ保存されます。」→
    「すべてのデータは端末内にのみ保存されます。外部に送信はしません。」
- 設定の説明は **結果** で書く。実装の語（描画・レンダリング・処理）を出さない。
  受身（保存されます・配置されます・調整されます）は可。
  - 悪い: 「余白は文字サイズに比例して描画されます。」
  - 良い: 「余白は文字サイズに合わせて広がります。」
- 位置で指示しない（「右上の」）。ただし空状態の「ここに配置されます」のような
  文脈的な指示語は可。
- 読者を急かさない・責めない・持ち上げない。

## 画面タイトル

| 項目 | 規則 |
|---|---|
| 文体 | 体言止め、または名詞句 |
| 句点 | なし |
| 長さ | 12字以内 |
| 例 | `読書統計` `表示設定` `フォントマネージャー` |

抽象語だけにしない。`設定` `情報` `管理` だけで終わる場合は、何の設定かを足す。
ただし「設定」画面そのもののタイトルは `設定` でよい。

## セクション見出し

| 項目 | 規則 |
|---|---|
| 文体 | 体言止め |
| 句点 | なし |
| 長さ | 16字以内 |
| 例 | `アプリの外観` `組式` `プリセット` |

## ラベル（指標名・項目名）

| 項目 | 規則 |
|---|---|
| 文体 | 名詞 |
| 句点 | なし |
| 長さ | 8字以内を目安。短縮より特定を優先 |
| 例 | `文字数` `連続読書記録` `読書日数` |

- 何の値かを名詞で特定する。動詞句にしない。
  - 悪い: `読んだ文字`
  - 良い: `文字数`
- 指標であることが曖昧なら語を足す。
  - 悪い: `連続読書`
  - 良い: `連続読書記録`
- 単位は値側に付ける。ラベルに単位を入れない（`3冊` / ラベルは `冊数`）。

## ボタン

| 項目 | 規則 |
|---|---|
| 文体 | サ変動詞は名詞形（保存・削除・追加）、和語は辞書形（閉じる・戻る・読み込む） |
| 句点 | なし |
| 長さ | 8字以内 |
| 例 | `保存` `削除` `上書き` `読み込む` `書き出す` `再試行` |

- 動詞を2つ入れない（「保存して閉じる」は禁止。主操作を1つ選ぶ）。
- 「はい / いいえ」を使わない。動作を書く（`削除` / `キャンセル`）。
- 「実行」「OK」だけで済ませない。何を実行するか書く。

## ダイアログ

| 項目 | 規則 |
|---|---|
| タイトル | 体言止めまたは動詞句、16字以内、句点なし |
| 本文 | です・ます、句点あり、80字以内。1文で足りるなら1文 |
| 例（削除） | タイトル `本を削除` / 本文 `『書名』と、この本の読書進捗・統計を端末から削除します。` |
| 例（上書き） | タイトル `プリセットを上書き` / 本文 `「$name」を上書きしますか？` |

- 本文でタイトルを言い換えない。
- **状態の説明を前置きしない。** タイトルで分かるなら問いだけでよい。
  - 悪い: `「$name」は既に保存されています。上書きしますか？`
  - 良い: `「$name」を上書きしますか？`
- 取り返しがつかない操作は、何が消えるかを名詞で列挙する。
- 確認は問い1つ。問いを2つ重ねない。

## ヘルパー（設定項目の説明）

| 項目 | 規則 |
|---|---|
| 文体 | です・ます |
| 句点 | あり（1文でも付ける） |
| 長さ | 48字以内、1文 |
| 例 | `システムのカラーテーマに追従します。` |

- ラベルの言い換えを書かない（ラベル「余白」に「余白を設定します」は不要）。
- 何が変わるかを書く。
- 単位や範囲は具体的に書く（「大きくなります」ではなく「1.0〜2.0字」）。
- 列挙より一般化する。ただしデータの扱いは明示する。
  - 悪い: `本棚・本文・読書進捗・設定・統計は端末内にのみ保存されます。`
  - 良い: `すべてのデータは端末内にのみ保存されます。外部に送信はしません。`
- 条件が問題なら、禁止形ではなく状態で書く。
  - 悪い: `組み込みプリセットと同じ名前は使用できません。`
  - 良い: `プリセット名が重複しています。`
- 「自動で」ではなく「自動的に」。
- パラメータを並べるより、因果のまとまりで書く。
  - 悪い: `文字サイズは字数・行数・行間から自動で決まります`
  - 良い: `文字サイズは端末幅と組式から自動的に調整されます。`

## エラー

| 項目 | 規則 |
|---|---|
| 文体 | です・ます |
| 句点 | あり（スナックバーは除く） |
| 長さ | 40字以内、1文 |
| 型 | 「何が失敗したか。」のみ |

- 主語は省略してよい（`フォントを追加できませんでした`）。
- **回復手順を足さない。** ユーザーが次の操作を選べる場合だけ、1文追加してよい。
- 原因を推測しない。「もう一度お試しください」を機械的に付けない。
- 読者を責めない。「正しく入力してください」は禁止。
- 状態が分かるなら、失敗ではなく状態で書く（`プリセット名が重複しています`）。

## スナックバー

| 項目 | 規則 |
|---|---|
| 文体 | です・ます |
| 句点 | なし（文中の句点は可） |
| 長さ | 40字以内、1文 |
| 例 | `3冊を本棚に追加しました` |

- 完了報告は結果だけ。手順を足さない。
- 取り消せる操作なら、アクションを1つだけ添える。

## 空状態

| 項目 | 規則 |
|---|---|
| 文体 | です・ます |
| 句点 | あり |
| 長さ | 見出し20字以内、本文60字以内 |
| 構成 | 見出し=状態、本文=操作したらどうなるか |
| 例 | 見出し `まだ本がありません。` / 本文 `EPUBファイルを追加するとここに配置されます。` |

- 画面の比喩ではなく、内容の状態を書く（`本棚はまだ空です` ではなく `まだ本がありません`）。
- 本文で機能の効能を語らない（`縦書きの組式で読めます` ではなく `ここに配置されます`）。
- 詩的な断片で余韻を作らない。
  - 悪い: `まだ読書記録がありません。本を開いて、最初の一頁を。`
  - 良い: `まだ読書記録がありません。本を開くと、読書時間が記録されます。`
- 見出しの句点は未検証。既存の見出しは句点なし。
- 感嘆符・絵文字・励ましを使わない。

## バッジ

| 項目 | 規則 |
|---|---|
| 文体 | 名詞1語 |
| 句点 | なし |
| 長さ | 4字以内 |
| 例 | `標準` `追加` `使用中` `読了` |

同じ意味のバッジを画面ごとに変えない（`標準` と `端末` を混在させない）。

## contentDescription

| 対象 | 規則 | 例 |
|---|---|---|
| アイコンボタン | 動作を書く | `設定を開く` `読書統計を開く` `EPUBを追加` |
| 状態アイコン | 状態を書く | `選択中` |
| 装飾アイコン | `null` | 隣に可視テキストがある場合 |
| 可変ラベル | 値そのまま | 書名 |

- 可視テキストがある要素に、同じ文言の `contentDescription` を付けない。
- 名詞だけにしない（`設定` ではなく `設定を開く`）。
- ただし `戻る` `閉じる` のような慣用動作は動詞のままでよい。
